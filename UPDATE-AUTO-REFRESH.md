# Обновление ReadLog: Автоматическое обновление списка файлов

## Что добавлено

✅ **Автоматическое обновление списка файлов** при появлении новых файлов в директории логов  
✅ **Двойной механизм обновления:**
  - Периодический опрос API каждые 5 секунд (резервный механизм)
  - WebSocket уведомления о новых/удалённых файлах (мгновенное обновление)
✅ **Отдельный WebSocket endpoint** `/ws/files` для уведомлений о файлах  
✅ **Логирование изменений** в консоли браузера  

## Как это работает

### Механизм 1: Периодический опрос (каждые 5 секунд)
- Фронтенд запрашивает список файлов через API `/api/files`
- Сравнивает с текущим списком
- Если есть изменения — обновляет список

### Механизм 2: WebSocket уведомления (мгновенно)
- Сервер отслеживает изменения в директории логов через `chokidar`
- При появлении нового файла отправляет уведомление `file_added` на `/ws/files`
- При удалении файла отправляет уведомление `file_removed` на `/ws/files`
- Фронтенд получает уведомление и мгновенно обновляет список

### Комбинированный подход
- WebSocket обеспечивает мгновенное обновление
- Периодический опрос гарантирует синхронизацию даже если WebSocket отключился

## Инструкция по обновлению

### Шаг 1: Скопируйте новые файлы на сервер

**На машине разработки:**

```bash
# Копируем собранные файлы фронтенда
scp -r dist/* jenkins@omega-test-02:/var/www/html/readlog/

# Копируем обновлённый server.js
scp server/server.js jenkins@omega-test-02:/opt/readlog/

# Копируем обновлённый websocket.js
scp server/websocket.js jenkins@omega-test-02:/opt/readlog/
```

### Шаг 2: На сервере установите права и перезапустите

**На сервере omega-test-02:**

```bash
# Установите права
sudo chown -R root:apache /var/www/html/readlog
sudo chown readlog:readlog /opt/readlog/server.js
sudo chown readlog:readlog /opt/readlog/websocket.js

# Перезапустите сервис
sudo systemctl restart readlog

# Проверьте статус
sudo systemctl status readlog
```

### Шаг 3: Очистите кэш браузера

В браузере нажмите **Ctrl + Shift + R** (или **Ctrl + F5**) для принудительной перезагрузки без кэша.

### Шаг 4: Проверьте работу

1. Откройте `http://omega-test-02.pmz.motor.loc:5555/`
2. Откройте консоль браузера (F12 → Console)
3. В другом терминале создайте новый файл лога:
   ```bash
   echo "test" > /opt/assembly_visual/logs/test-new-file.log
   ```
4. В консоли браузера должны появиться сообщения:
   ```
   ✓ File watcher WebSocket подключён
   📄 Новый файл: test-new-file.log
   📁 Список файлов обновлён: {новых: 1, удалённых: 0}
   ```
5. В списке файлов слева должен появиться новый файл

## Проверка WebSocket подключений

В консоли браузера (F12 → Console) выполните:

```javascript
// Проверка WebSocket для логов
const wsLogs = new WebSocket('ws://omega-test-02.pmz.motor.loc:5555/ws/logs');
wsLogs.onopen = () => console.log('✓ /ws/logs подключён');

// Проверка WebSocket для файлов
const wsFiles = new WebSocket('ws://omega-test-02.pmz.motor.loc:5555/ws/files');
wsFiles.onopen = () => console.log('✓ /ws/files подключён');
wsFiles.onmessage = (e) => console.log('📄 Уведомление о файле:', JSON.parse(e.data));
```

## Если проблема сохраняется

### Проверьте firewall

```bash
# Проверьте, открыт ли порт 5555
sudo firewall-cmd --list-ports

# Если порт не открыт, откройте его
sudo firewall-cmd --permanent --add-port=5555/tcp
sudo firewall-cmd --reload
```

### Проверьте SELinux

```bash
# Проверьте статус SELinux
getenforce

# Если SELinux включён, разрешите Node.js слушать порт 5555
sudo semanage port -a -t http_port_t -p tcp 5555
```

### Проверьте права на директорию логов

```bash
# Проверьте права
ls -la /opt/assembly_visual/logs/

# Пользователь readlog должен иметь право читать директорию
sudo chmod 755 /opt/assembly_visual/logs/
sudo chmod 644 /opt/assembly_visual/logs/*.log
```
